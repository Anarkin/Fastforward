# FEATURES-VIEWER

<!-- prettier-ignore-start -->

- What a file viewer can do, and how much of it Fastforward's viewer does

- Fastforward: ✅ Yes, 🟡 Partial, ❌ No

- Tier, a judgement call from what the viewers of Total Commander, Double Commander, Far Manager, Midnight Commander, Directory Opus, XYplorer and the preview of Explorer and Finder offer: Core is in nearly every viewer, Common in most, Advanced in a few, Niche in one or two, if any

- The key is the one the Lister of Total Commander uses for the feature, as most viewers of a file manager follow it; where Fastforward uses another, the notes say so

## Files

| Feature | What it does | Key | Tier | Fastforward | Notes |
| --- | --- | --- | --- | --- | --- |
| View a file | Show a file without its app | F3 | Common | ✅ Yes | In a viewer tab of its own, named after the file, with the icon of the viewer, keeping the text, hex or preview, the encoding, the language chosen and where it was in the text, the bytes, a PDF, a Markdown preview or an image at its real size while it is open, sideways too; its tab shown again comes back at once as it was left, its text, bytes and colors drawn as they were, its find open with its query, toggles and the match it was at, and the focus and caret where they were, the file read and searched anew only once it changed, a window reloaded as the settings are saved or the window it moved to bringing it back alike, from where it was, its find and its focus, kept by the main process, the file read and searched again; what it read kept for the three viewer tabs shown last; Escape closes it, F4 opens its file in an editor tab |
| Open from other tools | View a file from the commander or a git client | — | Common | ✅ Yes | F3 in the commander, inside an archive too, from a copy 7-Zip takes out, or Open with Viewer in the menu of a file, in the commander or on a part of a path anywhere; the button on the header of a file in git, F3, or Open with Viewer in the menu of its path, the working tree's from disk, a commit's or the index's as that version of the file |
| Restore after a restart | Open the files viewed again once the app starts | — | Common | ✅ Yes | Their tabs come back, a copy taken out of an archive too, the viewer read and searched anew, with the find of each and the match it was on, as the view of a tab is saved with it; the tabs of the commander that viewed a file, saved before the viewer was a tool of its own, come back as viewer tabs |
| Versions | Show a file as git kept it at a commit or in the index | — | Niche | ✅ Yes | V or the Version button of a file git tracks lists the uncommitted changes while the file on disk differs from its newest commit, which stands for it otherwise, the index while it differs from both HEAD and the disk, and every commit that changed the file, following renames, newest first, its short hash and date dimmed in columns before its subject, the one that deleted the file disabled, filtered by words, hash or date; a version shown in the tab of the file, under the path the file had then, which need not be there, its short hash after the name of the tab, read from a copy git takes out of it, made anew after a restart, its preview too; listed once its tab shows, in the background; Shift+F3 compares the version shown with the one before it in a diff tab; the button disabled for a file git keeps no version of, until its versions are listed too |
| Edit | Turn the file viewed into one edited | F4 | Core | ✅ Yes | F4 opens the file in an editor tab of its own, the cursor on the line at the top of the viewer, read in the encoding chosen there, or goes to the tab editing it already, as it was; a copy taken out of an archive or a commit, or a version of git, refused, saying so; F3 in the editor opens a viewer tab of its file, or goes to the one viewing it already; FEATURES-EDITOR says what it does |

## Text and bytes

| Feature | What it does | Key | Tier | Fastforward | Notes |
| --- | --- | --- | --- | --- | --- |
| Text | Show a file as text, of any size | — | Core | ✅ Yes | Read by byte position a screen at a time, so a gigabyte opens as fast as a kilobyte, each line of up to 64 KiB whole, as the diff shows it, a longer one in rows of 4 KiB, after an empty column as wide as the line numbers of the editor, so the text starts where the editor starts it, the column staying where it is as the text scrolls sideways, by whole columns on the wheel with Shift, Left and Right and its scrollbar alike; drawn as cells by the GPU with WebGPU, selected with the pointer, a double click taking a word and a third the line, and copied with Mod+C, the selection kept with its text wherever the file is scrolled to and however far it is dragged, though only the rows around the screen are held, and once its tab is shown again, with the copies of it marked at once, while the file, its encoding and the width of its bytes are as they were, the viewer saying so where a computer lets the app use no GPU; 2 |
| Hex | Show a file as bytes | — | Common | ✅ Yes | 1: its offset, 16 bytes a row and their characters, printable ASCII as it is and every other byte a dot, as on every system, drawn as cells as the text is; selected by whole bytes, pressed in either column and drawn in both, as Find marks them, a double click taking a byte in the hex column and a word in the other and a third the row, copied as hex digits from the hex column and as characters from the other, the other copies of the bytes selected marked in both columns; no cursor, the keys scrolling |
| Encodings | Read a text in its encoding | — | Common | ✅ Yes | E: Auto, from a byte order mark or, when not UTF-8, the code page of the system; UTF-16, the Windows, ISO-8859, KOI8, DOS 866 and Mac encodings, or the bytes, as many a row as fit, drawn as the characters of Hex are, the bytes of a binary file shown so on Auto |
| Syntax highlighting | Color the code of a file | — | Advanced | ✅ Yes | `shiki`, with VS Code's TextMate grammars, for files up to 10 MB; L chooses the language, or Plain Text |
| Wrap and whitespace | Wrap long lines, and draw the spaces, tabs and line ends | — | Common | ✅ Yes | W and `.`, whitespace on and wrapping off by default, as in the diff; wrapped at the column the editor wraps at, ↵ marking each break, as the editor and the diff mark them; in Hex and the bytes too, whitespace marking the bytes of a space, a tab, a carriage return and a line feed among the characters, the space by its dot and the rest by their signs, as text marks them, and every other control byte by its picture, the bytes past ASCII staying dots, what is copied and found staying as it was; the controls disabled where they don't apply, wrapping, the encoding and the language in Hex, the bytes and the previews, whitespace in the previews of images and PDFs and Real Size but for an image, rather than left out, so the toolbar stays as it is from mode to mode |
| Control characters | Draw the characters that have no shape of their own | — | Common | ✅ Yes | Each control character but the tab and the line ends as a picture of its own, the first and the last letter of its name, EC for the escape and DL for the delete, one above the other as its picture in Unicode has them, a column wide in the muted color of the signs of whitespace, whether whitespace is shown or not, as it marks a character rather than being text, and in the ink of a find match over it, where Chromium drew a box, nothing for the form feed or a gap for the delete, whichever a font of the system held; drawn by a font the app makes for them, as wide as a character of the monospace font of the settings, whatever that font has, and the pictures Unicode has for them, ␛ and the others, by it too, so a control character and its picture look alike; copied as the character itself; in the Markdown preview too, a form feed copied there as its picture |
| Find in the file | Search the text of a file | F7 | Common | ✅ Yes | Mod+F, through the whole file in its encoding, counting the matches and marking them in the text, the bytes and the hex, and on the track of its scrollbar; Aa matches the case, W whole words, across the slices it reads too, and .* a regular expression within a line; in a PDF, Aa and W through PDF.js, which has no regular expressions, its find kept with its tab and searched again as the PDF opens, stepping to the match it was on |
| Occurrences | Mark the other copies of the text selected | — | Advanced | ✅ Yes | Every copy of the text selected in the rows drawn, in its case and inside longer words too, once the selection has rested a quarter of a second, a text on one line of 200 characters at most and not of whitespace alone, the spaces at its ends left out, as a double click takes the space after a word; in the yellow and the text color of a find match, as the editor marks them, the selection kept; none while the search has a text; `text.highlightOccurrences` in the settings |
