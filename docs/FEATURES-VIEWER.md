# FEATURES-VIEWER

<!-- prettier-ignore-start -->

- What a file viewer can do, and how much of it Fastforward's viewer does

- Fastforward: ✅ Yes, 🟡 Partial, ❌ No

- Tier, a judgement call from what the viewers of Total Commander, Double Commander, Far Manager, Midnight Commander, Directory Opus, XYplorer and the preview of Explorer and Finder offer: Core is in nearly every viewer, Common in most, Advanced in a few, Niche in one or two, if any

- The key is the one the Lister of Total Commander uses for the feature, as most viewers of a file manager follow it; where Fastforward uses another, the notes say so

- What the viewer shares with the editor and the diff, how a text is drawn, whitespace, invisible characters, wrapping, scrolling, selecting and the toggles of a find, and with every tool, the tabs and windows, the keyboard, the menus, the lists, the look and the settings of the app, [FEATURES](FEATURES.md) says

## Files

| Feature | What it does | Key | Tier | Fastforward | Notes |
| --- | --- | --- | --- | --- | --- |
| View a file | Show a file without its app | F3 | Common | ✅ Yes | In a viewer tab of its own, named after the file, with the icon of the viewer, keeping the text, hex or preview, the encoding, the language chosen and where it was in the text, the bytes, a PDF, a Markdown preview or an image at its real size while it is open, sideways too; its tab shown again comes back at once as it was left, its text, bytes and colors drawn as they were, its find open with its query, toggles and the match it was at, and the focus and caret where they were, the file read and searched anew only once it changed, a window reloaded as the settings are saved or the window it moved to bringing it back alike, from where it was, its find and its focus, kept by the main process, the file read and searched again; what it read kept for the three viewer tabs shown last; Escape closes it, F4 opens its file in an editor tab |
| Open from other tools | View a file from the commander or a git client | — | Common | ✅ Yes | F3 in the commander, inside an archive too, from a copy 7-Zip takes out, or Open with Viewer in the menu of a file, in the commander or on a part of a path anywhere; a file in git on F3 or from Open with Viewer in the menu of its path, the working tree's from disk, a commit's or the index's as that version of the file |
| Follow changes | Show a file anew once it changes | — | Advanced | ✅ Yes | Watched while its tab shows, its text, bytes and previews read anew, a Markdown preview keeping the blocks a change leaves alone and a PDF its focus and find; a file changed while its tab was away read anew once shown again; told by its size and dates and by its first and last 64 KB, so a change that keeps its size and dates, as on a FAT drive or a share, is seen where it reaches either end, F2 and Ctrl+R reading it anew wherever it changed; one gone saying it can't be read |
| Restore after a restart | Open the files viewed again once the app starts | — | Common | ✅ Yes | Their tabs come back, a copy taken out of an archive too, the viewer read and searched anew, with the find of each and the match it was on, as the view of a tab is saved with it; the tabs of the commander that viewed a file, saved before the viewer was a tool of its own, come back as viewer tabs |
| Versions | Show a file as git kept it at a commit or in the index | — | Niche | ✅ Yes | V or the Version button of a file git tracks lists the uncommitted changes while the file on disk differs from its newest commit, which stands for it otherwise, the index while it differs from both HEAD and the disk, and every commit that changed the file, following renames, newest first, its short hash and date dimmed in columns before its subject, the one that deleted the file disabled, filtered by words, hash or date; a version shown in the tab of the file, under the path the file had then, which need not be there, its short hash after the name of the tab, read from a copy git takes out of it, made anew after a restart, its preview too; listed once its tab shows, in the background; Shift+F3 compares the version shown with the one before it in a diff tab; the button disabled for a file git keeps no version of, until its versions are listed too |
| Edit | Turn the file viewed into one edited | F4 | Core | ✅ Yes | F4 opens the file in an editor tab of its own, the cursor on the line at the top of the viewer, read in the encoding chosen there, or goes to the tab editing it already, as it was; a copy taken out of an archive or a commit, or a version of git, refused, saying so; F3 in the editor opens a viewer tab of its file, or goes to the one viewing it already; FEATURES-EDITOR says what it does |

## Text and bytes

| Feature | What it does | Key | Tier | Fastforward | Notes |
| --- | --- | --- | --- | --- | --- |
| Text | Show a file as text, of any size | — | Core | ✅ Yes | Read by byte position a screen at a time, so a gigabyte opens as fast as a kilobyte, each line of up to 64 KiB whole, as the diff shows it, a longer one in rows of 4 KiB; selected with the pointer and copied with Mod+C, Mod+A selecting the whole file, which the main process copies, read whole in the encoding shown, up to 50 MB, a notice saying so of a larger one, the selection kept with its text wherever the file is scrolled to and however far it is dragged, though only the rows around the screen are held, and while its encoding and the width of its bytes are as they were; the rest as [FEATURES](FEATURES.md#common-text) says; 2 |
| Hex | Show a file as bytes | — | Common | ✅ Yes | 1: its offset, 16 bytes a row and their characters, printable ASCII as it is and every other byte ¤, as on every system, the pointer resting on one naming its byte in a tooltip, as Byte 0x1B ESCAPE, in the bytes too, drawn as cells as the text is; selected by whole bytes, pressed in either column and drawn in both, as Find marks them, a double click taking a byte in the hex column and a word in the other and a third the row, copied as hex digits from the hex column and as characters from the other, Mod+A selecting every byte of the file, which the main process copies as hex digits, up to 16 MB, a notice saying so of a larger one, the other copies of the bytes selected marked in both columns; no cursor, the keys scrolling |
| Encodings | Read a text in its encoding | — | Common | ✅ Yes | E, as [FEATURES](FEATURES.md#common-text) says, Auto naming the one it read the file in; or the bytes, as many a row as fit, drawn as the characters of Hex are, the copies of the bytes selected marked by their value, as Hex marks them, the bytes of a binary file shown so on Auto |
| Tab width | Show how wide a tab is drawn and why, and draw it wider or narrower | — | Advanced | ✅ Yes | The button Tab Size: 4 lists where the width comes from, a width chosen for the tab, `tab_width` or `indent_size` of the `.editorconfig` of the file, opened on a click, and `text.tabSize` of the settings, the one used checked, and draws the tabs of the tab 2, 4 or 8 columns wide until it is set back, kept with the tab; disabled but in the text |
| Syntax highlighting | Color the code of a file | — | Advanced | ✅ Yes | As [FEATURES](FEATURES.md#common-text) says |
| Wrap and whitespace | Wrap long lines, and draw the spaces, tabs and line ends | — | Common | ✅ Yes | W and `.`, whitespace on and wrapping off by default, as in the diff, as [FEATURES](FEATURES.md#common-text) says; in Hex and the bytes too, whitespace marking the bytes of a space, a tab, a carriage return and a line feed among the characters, the space by its dot and the rest by their signs, as text marks them, and every other byte that is no printable ASCII drawn as ¤ whether whitespace is shown or not, so a byte that is a dot is told from one that is not, what is copied and found staying as it was; the controls disabled where they don't apply, wrapping, the encoding and the language in Hex, the bytes and the previews, whitespace in the previews of images and PDFs and Real Size but for an image, rather than left out, so the toolbar stays as it is from mode to mode |
| Control characters | Draw the characters that have no shape of their own | — | Common | ✅ Yes | As [FEATURES](FEATURES.md#common-text) says; in the prose of a Markdown preview as ¤ too, in the muted color of the signs, copied as the character itself |
| Invisible characters | Draw the characters that show nothing, take no room or turn text around | — | Advanced | ✅ Yes | As [FEATURES](FEATURES.md#common-text) says; the byte order mark that starts a file of UTF-8 left out of its first line, as the editor leaves it out; not in the prose of a Markdown preview, which the browser draws as GitHub does, its code blocks drawing them |
| Find in the file | Search the text of a file | F7 | Common | ✅ Yes | Mod+F, through the whole file in its encoding, counting the matches and marking them in the text, the bytes and the hex, and on the track of its scrollbar; Aa matches the case, W whole words, across the slices it reads too, and .* a regular expression within a line; in a PDF, Aa and W through PDF.js, which has no regular expressions, its find kept with its tab and searched again as the PDF opens, stepping to the match it was on; in a Markdown preview, without leaving it, through what it shows and what its closed details hold, opening one to go to a match in it, as a browser does, its prose within a block, across bold, links and code in a line, and the lines of its code blocks, in the order of the document, every match in the find yellow and the current one orange, as in every view, and on the track of its scrollbar as a file viewed marks them, while it has one, Aa, W and .* as anywhere, kept with its tab |
| Occurrences | Mark the other copies of the text selected | — | Advanced | ✅ Yes | As [FEATURES](FEATURES.md#common-text) says |
